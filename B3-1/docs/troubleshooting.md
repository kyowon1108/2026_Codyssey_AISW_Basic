# 트러블슈팅 — IAM 역할 사용 직후 `AccessDenied`

| 단계 | 2026-10-02 재실습 기록 |
|---|---|
| 증상 | 역할 생성 직후 `aws sts get-caller-identity --profile codyssey-b3-1-evidence`가 `sts:AssumeRole`의 `AccessDenied`로 실패 |
| 가설 | 새 역할의 신뢰 정책·인라인 정책이 아직 반영되지 않았을 가능성 |
| 검증 | 정책을 바꾸지 않고 약 10초 후 같은 명령을 재실행하자 전용 역할 ARN을 반환했다. [성공 출력](evidence/00-iam-role.txt) 보관 |
| 조치 | 관리자 권한을 추가하지 않고 잠시 기다린 뒤 재시도 |
| 결과 | 전용 역할로 VPC·SG·EC2를 만들고 검증했다. 연결된 관리자 관리형 정책은 없었다 |
| 재발 방지 | 역할 생성 후 `AssumeRole` 성공을 먼저 확인한다. 반복 실패하면 신뢰 정책과 호출자 권한을 조사한다 |

전파 지연은 전후 결과에 근거한 추론이며, AWS 내부 상태 로그로 확정한 원인은 아니다.
